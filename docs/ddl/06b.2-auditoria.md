# 06b.2 auditoria

DDL del esquema `auditoria`: bitácora de acciones de usuario y bitácora de movimientos de stock. Ambas son **append-only**: sin `UPDATE`, sin `DELETE`, sin `is_active`. Referencia de revisión del modelo de [06.2 auditoria](../modelo-datos/06.2-auditoria.md).

```sql
CREATE SCHEMA IF NOT EXISTS auditoria;

-- Append-only: sin UPDATE ni DELETE a nivel de permisos de BD
CREATE TABLE auditoria.bitacora_accion (
    id              BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    usuario_id      BIGINT NULL REFERENCES nucleo.usuario(id),
    modulo          VARCHAR(30)  NOT NULL,
    entidad_tipo    VARCHAR(50)  NOT NULL,
    entidad_id      BIGINT,                                  -- referencia debil
    accion          VARCHAR(30)  NOT NULL
                    CHECK (accion IN ('crear','editar','borrado_logico','denegado')),
    estado_anterior JSONB,
    estado_nuevo    JSONB,
    direccion_ip    INET,
    creado_en       TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE auditoria.bitacora_stock (
    id               BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    local_id         BIGINT NOT NULL REFERENCES nucleo.local(id),
    local_destino_id BIGINT NULL REFERENCES nucleo.local(id),
    lote_id          BIGINT NULL REFERENCES inventario.lote(id),  -- FK solo si es material continuo
    tipo_item        VARCHAR(20) NOT NULL CHECK (tipo_item IN ('material','variante')),
    item_id          BIGINT,                                     -- referencia debil
    tipo_movimiento  VARCHAR(30) NOT NULL,
    cantidad         NUMERIC(12, 4) NOT NULL,
    codigo_um        VARCHAR(10) NOT NULL,                       -- codigo de la unidad de medida (ej: 'm', 'm2')
    motivo           VARCHAR(200),
    usuario_id       BIGINT NOT NULL REFERENCES nucleo.usuario(id),
    creado_en        TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX idx_bitacora_accion_usuario ON auditoria.bitacora_accion (usuario_id, creado_en DESC);
CREATE INDEX idx_bitacora_accion_entidad ON auditoria.bitacora_accion (modulo, entidad_tipo, entidad_id);
CREATE INDEX idx_bitacora_stock_item ON auditoria.bitacora_stock (tipo_item, item_id, creado_en DESC);
CREATE INDEX idx_bitacora_stock_local ON auditoria.bitacora_stock (local_id, creado_en DESC);
```

> Nota de orden: `auditoria.bitacora_stock` referencia `inventario.lote`, que se crea después. En PostgreSQL la FK se valida al insertar datos, no al crear la tabla, pero la migración de Django debe aplicarse en el orden `nucleo → catalogo → inventario → auditoria`.
